## 0. 合并后的文档使用与提交纪律

### 0.1 为什么合并
- 减少 md 文件数量，降低找文档的成本。
- 减少多人同时改多个规划文件导致的分支合并冲突。
- 一份文档同时承载：周期节奏、任务清单、验收标准、Issue 契约。

### 0.2 提交纪律（减少合并麻烦）
| 场景 | 做法 |
|---|---|
| **规划更新** | 每个 cycle 初改一次本文件；不要每个小任务都改。 |
| **代码提交** | 个人在本地/自己 fork 开发；cycle 末一次性合入 `基础骨架`，最多 W1 末 + W2 末两次。 |
| **TASKBOARD 移动卡片** | 同样只在 cycle 初/末或重大阻塞时移动；日常进度在 Issue 评论里更新。 |
| **紧急阻塞** | 单独提 hotfix 合入，并在本文件「风险」区标注。 |

> 原则：**一个 cycle 内，规划文档 + 代码 + 看板尽量只合 1~2 次**，避免天天 merge。

## 5. 评委可测试交付标准（Cycle 1 DoD）

> 这是本 cycle 的「完成定义」。评委线上实操时逐项可验。

- [ ] **可达性**：国内网络打开 URL 无超时、无白屏。
- [ ] **五 Skill 实操**：diagnose/plan/practice/info/package 均可进入、流式输出、三态齐全。
- [ ] **真实 AI 调用**：配置 DeepSeek key 时真实响应；无 key/断网自动降级 stub 不崩。
- [ ] **跨会话记忆**：上一轮对话提取的画像，下一轮可被召回（评委可现场验证「记得我」）。
- [ ] **长期画像可编辑**：登录页可见画像，可修改并持久。
- [ ] **KPI 看板**：四图 + 任务流卡片；空态/加载/错误三态；趋势图 7/14/30 切换。
- [ ] **成长体系**：打卡日历着色 + 今日状态 + 积分显示。
- [ ] **简历面板**：展示抽取字段 + 优化建议。
- [ ] **招聘推送**：展示近期招聘会 + 投递链接可点。
- [ ] **套餐页**：档位展示 + 模拟购买流程。
- [ ] **跨端兼容**：Chrome / Safari / 微信内置浏览器均可操作；移动端响应式无溢出。
- [ ] **健壮性**：非法输入/空数据/网络异常均不白屏崩溃。

> 注：带 Supabase 依赖的项（画像可编辑/成长/简历）若 Cycle 1 未就绪，则作为 Cycle 2 DoD，但需在本文件里标注。

## 6. A / C / D Issue 契约（可直接建 Issue）

> 标题建议前缀 `[A]` / `[C]` / `[D]`。以下按角色拆分，避免一个 Issue 太大。

### [A] 部署可用性 + Supabase 配置（P0 前置）
- **背景**：评委只点 URL；B/C 成长体系依赖 Supabase。
- **交付物**：
  1. 国内可达 URL（Vercel 默认或自有域名）。
  2. Supabase 项目：`URL` + `anon key` + `RLS` 策略。
  3. 将 URL/key 注入 Vercel / Worker 环境变量。
- **验收**：URL 国内可开首页；Supabase 可读写；真实 AI 可调用。
- **节点**：W1 周末前。
- **关联**：T-001、T-004。

### [C-1] Supabase Schema + 流式 API + 画像接口（W1 末）
- **交付物**：
  - `profiles` / `checkins` / `points` / `skill_events` 四表 + RLS。
  - 五 Skill `POST /api/skill/[name]` 返回 SSE/ReadableStream，字段约定文档。
  - `GET/POST /api/memory/profile` 画像读写。
- **验收**：B 前端可联调；无 key 时返回 stub 不崩。
- **依赖**：A 的 Supabase（W1末）。
- **关联**：T-015、T-014、T-018。

### [C-2] 长记忆压缩 + 沙箱（W2）
- **交付物**：
  - T-016 压缩：Supabase 存储；`R=e^(-t/S)` 衰减；混合压缩；异步 Observer；阈值 C 给默认。
  - T-017 沙箱：输入校验 + 调用白名单 + 超时（建议 30s）+ 单用户频次限额。
  - T-011 简历抽取：五 Skill 对话后抽取字段落入 `profiles`（`school`/`major`/`gpa`/`skills`/`target`/`interests`/`personality`/`painpoints`）。
- **验收**：压缩产出画像可跨会话召回；沙箱拦截越权/超时。
- **依赖**：T-018 schema。
- **关联**：T-009、T-016、T-017、T-011。

### [D] 验收与测试（W2 D3–D4）
- **交付物**：
  - 评委可测试 12 项逐项勾选。
  - 跨端兼容矩阵（Chrome/Safari/微信内置，≤375px）。
  - 埋点数据核对（skill_events/打卡/积分/画像）。
  - 性能与降级测试（无 key/断网 stub、首屏、长对话）。
  - 健壮性安全测试（非法输入/空数据/特殊字符/XSS）。
- **验收**：输出验收报告 + 缺陷清单（附截图/录屏）。
- **依赖**：B/C 功能就绪（W2 初）。
- **关联**：D-001~D-005。
