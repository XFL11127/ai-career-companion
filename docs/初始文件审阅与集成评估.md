## 二、系统性技术总结（技术流）

### 2.1 产品原理（来自 F1）

- **定位**：面向双非院校学生的轻量化 AI 学职成长陪伴助手（iCAN 智能体赛道）。
- **核心差异（5 点）**：双非垂直定位 / 三层记忆（Copilot 式） / 五 Skill 闭环 / 极致轻量（免登即用、首屏 <200KB） / 数据驱动（四层 KPI + 三级看板 + 预测模型）。
- **价值闭环**：信息差 → 机会差 → 信心差（恶性循环）→ 用「差距可量化 / 路径可执行 / 信息差填平 / 轻量免登」打断。
- **北极星指标**：周活跃学习者数 WAL（AARRR + OSM 框架）。

### 2.2 七层架构与模块职责（F1 Table10 + F3 §5 + F6 §一）

| 层 | 计划组件 | 实际实现（F6） | 职责边界 |
|---|---|---|---|
| L1 接入层 | Web H5 / PWA / API Gateway | Next.js 14 App Router（**未做 PWA/Capacitor**） | 浏览器入口、BFF 反向代理、移动适配 |
| L2 交互层 | 卡片引擎 / 状态看板 / 轻提醒 / 情绪感知 | 卡片式输出 ✅、KPI 看板 ✅、**轻提醒/情绪感知缺失** | 卡片渲染、看板可视化、状态管理 |
| L3 Skill 层 | Skill 0-4 + 画像驱动 + LLM 路由 | diagnose/plan/practice/info/package ✅ | 五 Skill 业务逻辑、流式输出、画像注入 |
| L4 记忆层 | Mem0 适配器 / 压缩 / 多信号检索 | **自研 bge-m3 语义召回 + 关键词兜底**（无 Mem0 SDK） | L1 会话/L2 画像/L3 知识（L3 降级为静态知识库） |
| L5 分析层 | ETL / KPI 引擎 / 预测 / 报告 | KPI 引擎 ✅、预测/报告缺失 | 指标计算、看板聚合 |
| L6 数据层 | IndexedDB / PG+pgvector / Redis | IndexedDB(L1) ✅、Supabase PG(`float8[]` 非 pgvector) ✅、**Redis 未用** | 持久化、向量存储（应用层余弦） |
| L7 基础设施 | Vercel / Workers / Supabase / LLM API | Workers ✅、Supabase ✅、DeepSeek ✅、**Vercel 前端未部署→现用 Vercel** | 部署、运行时、密钥 |

### 2.3 五 Skill 模块职责与依赖（F1 Table11 + F6 §二）

| Skill | 职责 | 上游依赖 | 下游落库 |
|---|---|---|---|
| Skill 0 破局诊断 | 五维差距扫描 → 差距雷达 `radar` | 用户画像 + DeepSeek | `memory(layer=diagnosis)` + `skill_events` |
| Skill 1 路径规划 | 差距 → 可执行成长路径（`generateObject`） | Skill 0 雷达 | `skill_events` |

**关键依赖链**：`packages/types`（zod 共享契约，**单一事实源**）→ 前端 `web` + 后端 `worker` + LLM 包 `packages/llm` 均依赖它；改契约必双端 `type-check`。前端经 BFF `/api/skill/*` → Worker `/skill/*` → `runSkill/streamSkill` → DeepSeek。

### 2.4 三项关键技术偏离（F6 §三，答辩重点）

| 偏离 | 计划 | 实际 | 为何更优 |
|---|---|---|---|
| ① 记忆 | Mem0 开源版 | bge-m3 自研召回 + 关键词兜底 | Mem0 SDK 默认 OpenAI embedding 要钱/出网，Cloudflare Workers 跑不了；bge-m3 免费、零出网、中文好 |
| ② 后端框架 | Hono | 原生 `fetch` 零依赖单文件 | 包体更小、冷启动更快、无第三方版本风险 |
| ③ 向量存储 | PG + pgvector | `float8[]` + 应用层余弦 | 避 pgvector 扩展依赖 + Auth 外键冲突；小样本足够快 |

### 2.5 八项缺口（F6 §四，优先级）

- **P0（阻断评审）**：① 国内访问不可达（`*.workers.dev` 被 GFW 污染）→ 绑自有域名。
- **P1（加分项）**：② Redis 限流/缓存 ③ Moonshot 备用模型回退 ④ 埋点 SDK + GitHub Actions 定时报告。
- **P2（体验）**：⑤ PWA/Capacitor ⑥ 情绪感知 ⑦ 轻提醒 ⑧ 预测模型（数据不足时正确克制，暂不实现）。

### 2.6 部署拓扑（F4 + F5，注意版本冲突）

- **现行（正确）**：前端 `apps/web` 自包含直连 DeepSeek → Vercel（Root=`apps/web`，仅 `DEEPSEEK_API_KEY` 必填）。不再需要 Worker、不再需要 `NEXT_PUBLIC_WORKER_URL`。
- **后端的 Worker**：`npx wrangler deploy --config apps/worker/wrangler.toml`（必须 `--config`）；变量 `DEEPSEEK_API_KEY` + `SUPABASE_*`。
- **⚠️ F5 已过时**：仍写 `pnpm install`，但 workspace 内部依赖 `*` 写法致 pnpm 装内部包 404（见 `项目说明.md` §10 环境多发问题）。当前 CI 与部署均改 **npm**。

### 2.7 团队与质量约定（F1 §7.4 + F2 风险 + F6）

- 4 人：A 队长（统筹，不写核心代码）/ B 前端 / C 后端 AI / D 数据测试。

## 四、后续文件变更的工作流方案

### 4.1 分支策略（已与团队对齐）

```
基础骨架  (长生命周期活跃分支 = 部署目标 = 默认分支)
   ├── feat/<issue-id>-<短描述>   (短生命周期功能分支，从 基础骨架 切)
   ├── fix/<issue-id>-<短描述>    (缺陷修复分支)
   └── docs/<短描述>              (文档/部署指南变更)
```
- 禁止直接 push `基础骨架`；所有改动走 PR。
- 保护分支：启用「需 PR 评审 + CI(npm) 通过」才能合入（呼应 F1 §7.4）。
- 部署分支 = `基础骨架`（Cloudflare/Vercel 均监听它）。

### 4.2 代码审查流程

| 步骤 | 动作 | 责任 |
|---|---|---|
| 1 | 开 feature 分支，本地 `npm run type-check` 0 报错 | 作者 |
| 2 | 提 PR，描述写 `Closes #<issue号>`，填 PR 模板 | 作者 |
| 3 | **CI(npm) 三个 job（lint/typecheck/build）必须全绿** | 自动 |
| 4 | ≥1 人评审（F1 §7.4 约定）；可用 WorkBuddy `code-reviewer` / `silent-failure-hunter` Agent 预审 | 评审人 |
| 5 | 合入 `基础骨架` → Projects 自动移卡「待审核」→ 队长验收移「完成」 | 队长 |

### 4.3 是否用 Issue 跟踪变更需求与讨论？

**结论：用 Issue 跟踪「行动项」，用 Discussion 跟踪「开放式讨论」。**

**适用 Issue 的场景（必须建）：**
- 新增功能 / 补 F6 缺口（P0 国内域名、P1 Redis/Moonshot/埋点）
- Bug 修复（含 CI 失败、部署异常）
- 架构决策讨论（如「是否引入 pgvector」「是否加 PWA」）→ 讨论完落 ADR
- **文件变更提案**（如「把 F5 标注过时」「新增 §12 索引」）→ 提案即 Issue

**适用 Discussion 的场景（不建 Issue）：**
- 开放式问答、头脑风暴、技术选型未定前的探索
- 纯信息同步、非行动项

**Issue 最佳实践（结合 F1 §8.5 + 已建模板）：**
1. 用 `.github/ISSUE_TEMPLATE`（feature/bug），强制填 **需求来源 / 优先级 / 验收标准**。
2. 标签体系：`priority/P0|P1|P2`、`risk/high|medium|low`（对齐 F1 风险矩阵）、`area/frontend|backend|deploy|doc`。
3. PR 用 `Closes #编号` 关联，实现「需求→代码→评审」全链路可追溯。
4. 里程碑（Milestone）映射 F2 的 M1-M4（需求确认/核心功能/系统集成/线上交付）。
5. 每个 Sprint Review 同步过 🔴→🟡→🟢 风险（F1 §8.5 双周机制）。

**「文件变更」标准动作示例：**
> 提案「把 Cloudflare 部署指南标注过时」→ 建 Issue `#X`（需求来源：本次审阅）→ 开 `docs/mark-f5-stale` 分支 → 改 F5 加过时横幅 + 在 `项目说明.md` 加 §12 索引 → PR `Closes #X` → 评审合入 → TASKBOARD 移卡。
